# rgx-tv A/B/C transcript

Paired three-arm runs of the pack-store protocol (`scripts/tv-vs-rg.sh`):
count gate first, arms paired inside each round, order rotated, minimum of
7 rounds reported, floor ±3%. Each run rebuilds its store from the corpus
at its own date. **Runs are not interchangeable**: absolute milliseconds
drift across sessions, and the ratio is only as good as the reference arm's
placement. The 2026-10-10 run's ripgrep arm is the outlier against every
other measurement of this corpus on this machine (see the note at the
bottom); the project quotes the 2026-10-11 run.

**Two hosts are now on file.** The Windows 7950X3D runs are §Run 2026-10-11
and §Run 2026-10-10; the Linux Ryzen 7 255 run is §Run 2026-10-11 (Linux).
Absolute milliseconds are per host and are never comparable across the two.
Ratios are the portable content, and even they move at the low end — see the
cross-host note at the end of the Linux section.

### Cross-host note

The architecture claim survives the host change: the pack engine is faster
than both direct paths on every pattern, with identical counts, on a second
OS and a second CPU class. The **headline multiplier does not travel**.
Windows quoted 2.79x–3.38x vs rg; this host gives 1.55x–3.13x, and the low
end moved a full point (`e.` 2.79x → 1.55x) while `let mut` rose slightly
(3.38x → 3.13x is inside the spread of a different thread count and a
different reference binary). Break-even improved on this host because the
store builds in 998 ms against 2.26 s. Quote a multiplier only with its
host, its thread count, and its run date — which is what this file has
always said, now with a reason.

## Verdict rules

A ratio inside ±3% is a tie. Overlapping samples are not a result. The count
gate withholds every timing line where the arms disagree on how many lines
matched. `tv-vs-rg.sh` reports the minimum of N paired rounds without the
distribution gate the main dashboard has, so between-session ratio drift
exceeds ±3% here; compare runs by where their *reference* arm lands, not by
the headline multiplier.
