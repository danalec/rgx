# rgx-core

The engine. Every `rgx` adapter is written against the `Adapter` trait
defined here, and `process()` is what turns a file into searchable units:
it owns adapter resolution, recursion, depth limits, member caps and bail
semantics, so those live in one place rather than once per adapter. The
byte searches, the JSON arena and the pack store are here too.

The crate is `#![no_std]` + `alloc`; the `std` feature decides what else it
may use, and what it turns on is the typed error chain, the profiler map
and the `f64` JSON parser. An embedder that wants to search its own files
without the standard library can have the engine and the same vector
kernels the full build uses.

## The adapter contract

`Adapter::extract` is a sync function over a byte slice — no async, no
streams, no subprocess in the core model.

- `Outcome::Text` — searchable text, already encoding-normalized.
- `Outcome::Members` — `(virtual path, bytes)` pairs to recurse. Adapters
  never recurse themselves.
- `Outcome::Bail` — "not my file". The chain continues with the next
  candidate, and a file every adapter declines reaches the raw searcher
  with its bytes intact. `bail!` arrives the same way, but stops the chain
  at the first failure and adds a note, so it is reserved for failures
  worth reporting.

`available()` returns false when the adapter cannot run here — a missing
external binary — and the registry skips it. In-process adapters always
return true.

## Reach and Policy

`reach()` says what an adapter's output is for, relative to the bytes on
disk. `Reach::Reveal` is the default: the file is a container or a binary
format, so the adapter surfaces bytes the raw searcher cannot reach.
`Reach::Render` is for a transforming adapter whose rendering is lossy
over a file that is already text. `reach_needs_bytes()` is true when that
answer depends on the file rather than the extension, and only those
adapters pay a read to find out.

`Policy` chooses which view is searched. `Source` is the default and the
only one under which rgx stays a superset of ripgrep on a `Render` format.

## Registry

Adapters are indexed by extension, so resolution costs the candidates for
that extension rather than the whole registry. The first matching
available adapter wins and a bail falls through to the next. Repeated
extensions inside one adapter's own list are collapsed, because the index
otherwise pushes that adapter once per literal.

Byte scanning is the upstream `memchr` crate 2.x, re-exported as
`pub mod memchr` so every call site keeps the `rgx_core::memchr::*` path it
used when the in-house module was still in the tree. The *dispatch* is this
crate's own: `src/detect.rs` answers "may this CPU run AVX2?" by hand
(CPUID and XGETBV, no `std`), and `src/memchr/dispatch.rs` picks the kernel
from that answer. So the `no_std` build reaches the same AVX2 kernel the
`std` build reaches, and the two configurations' numbers are comparable.
The upstream crate still supplies the searchers themselves, and its own
compile-time choices -- SSE2, and NEON on aarch64 -- are what run when the
CPU has no AVX2.

The substring search is the one thing that is not the upstream crate's:
`src/memchr/memmem.rs` is this crate's own, because the upstream packed-pair
kernel cannot be reached without `std`.

`pub mod charset` decodes a byte stream in an encoding the data itself
names — a MIME part's `charset=`, an HTML `<meta charset>`, an RFC 2047
header. The single-byte tables are generated by
`scripts/gen_charset_tables.py` from the reference implementation, and the
multi-byte CJK ones — Shift_JIS, EUC-JP, Big5, EUC-KR and GB18030, whose
high half is a *pair* of bytes — by `scripts/gen_charset_mb_tables.py`,
which also writes the fixtures that test them. The encodings that declare
themselves as the stream goes — ISO-2022-JP and UTF-7 — have their
structure generated by `scripts/gen_charset_state_tables.py`, and the
decoder is a small state machine over it. `decode_lenient` is the
fallback that never loses a byte: valid UTF-8 is kept as it is, anything
else is read as Latin-1.

## Feature flags

- `std` (default) — the typed error chain, the profiler map and the `f64`
  JSON parser, and nothing else that matters. Off, the crate stays
  `no_std + alloc`, and the byte searches still reach the same AVX2 kernel:
  the probe that decides is this crate's own, and it does not need `std`.
- `sha256-hw` (default) — runtime-detected SHA-NI on x86_64 and ARMv8
  SHA2 on aarch64, falling back to the scalar path.
- `tv`, `tv-runtime` — the pack-store storage tier. Not in `default`.
